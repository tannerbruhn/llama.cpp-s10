# llama.cpp for the Samsung Galaxy S10

> [!NOTE]
> **This branch runs LLMs on a Galaxy S10 (Exynos 9820, Mali-G76, 8 GB) under postmarketOS.** It is the PrismML
> llama.cpp (for the ternary Bonsai models) plus S10 work on top. This port was AI-written and tested on the phone.
>
> - ARM CPU kernels for ternary PTQ1_0: a lean block decoder, a two-row kernel with prefetch, and a prompt kernel
>   that decodes each row pair once (`ggml/src/ggml-cpu/`).
> - A Mali GPU assist (`ggml/src/ggml-cpu/s10-gpu-assist.c`, CMake `GGML_CPU_S10_GPU_ASSIST`): the GPU computes part
>   of every PTQ1_0 matrix product over OpenCL (Mesa Rusticl). Ternary Bonsai 2 27B: 0.48 -> 1.21 tok/s generation.
> - A two-token IQ4_NL kernel that reads the weights once for 2-token batches (+21%; speculative-decoding checks),
>   a faster Q4_0 4x4 gemv, and `LLAMA_ROUTER_DEFAULT_MODEL` for the router server.
> - Runs Ornith 1.5 9B with its own MTP layer (multi-token prediction): +18% on code, +35% on edits.
> - **int2 CPU kernel** (`ggml/src/ggml-cpu/s10-int2.c`, `GGML_S10_INT2=all`): the CPU's share of each
>   PTQ1_0 matrix is re-encoded once in RAM as 2-bit codes and computed with a third fewer NEON instructions,
>   bit-identical to the PTQ1_0 path (`tests/test-s10-int2.cpp`, greedy text and perplexity unchanged). Costs about
>   +0.6 GB of RAM for the 27B; `GGML_S10_INT2_POOL=/dev/s10cpumem` can place the first part in otherwise unused
>   memory (driver in the recipes repo). Bonsai 2 27B with the GPU assist at share 0.35: tg24 1.235 -> 1.34 tok/s;
>   long answers through the server 0.74 -> 1.03-1.17 tok/s (fewer heat pauses). In daily use on two phones since
>   2026-11-17 (15 h of unattended serving without a restart on one of them).
> - Experimental: two phones over llama.cpp RPC. Layer split (`--rpc`, `-ngl 32`): the 27B at 1.16 tok/s over
>   Wi-Fi, both phones cool, ~4 GB free on the first. Tensor parallel (`-sm tensor`) now works with the
>   Hadamard-folded Bonsai models (per-weight sign vectors, `src/llama-model.cpp`; greedy output identical to a single
>   process). Over Wi-Fi it reaches ~0.67 tok/s (rpc-servers with `OMP_WAIT_POLICY=active GOMP_SPINCOUNT=3000000`, and
>   the all-reduce now adds small partials in host memory instead of launching a graph: +18%). The limit is Wi-Fi's
>   cost per 20 KB exchange (~5-6 ms, the same with a 2 ms phone-to-phone link), ~128 per token; over Ethernet the
>   estimate is ~1.4 tok/s, above one phone. `GGML_RPC_COMM_PROFILE=1` on the servers prints the per-sync breakdown. Known issue: a
>   long-lived `ggml-rpc-server` keeps the GPU-assist/int2 copies of a disconnected client's weights; restart it
>   before each new load.
> - Experimental, default off: CPU-GPU overlap tuning (`GGML_S10_GPU_LATE`, `GGML_S10_GPU_QNEON`) and thread-0
>   placement (`GGML_S10_T0LAST`): about +2% and within noise, kept for further work.
>
> **The S10 project.**
>
> These four repos turn an old Samsung Galaxy S10 (SM-G973F, Exynos 9820) into a small always-on LLM server under
> postmarketOS. The kernel and U-Boot forks are general S10 support; the other two are the LLM side.
>
> - [exynos-9820-mainline-linux](https://github.com/tannerbruhn/exynos-9820-mainline-linux): kernel (Wi-Fi, charger,
>   Mali-G76 GPU through Panfrost)
> - [u-boot](https://github.com/tannerbruhn/u-boot): bootloader and device tree (Wi-Fi, reserved memory, GPU node and
>   clocks)
> - [llama.cpp-s10](https://github.com/tannerbruhn/llama.cpp-s10): inference (ternary CPU kernels, Mali GPU assist)
> - [s10-llm-recipes](https://github.com/tannerbruhn/s10-llm-recipes): models, quantization, server setup, measured
>   numbers
>
> Updates: [@t24_lab on X](https://x.com/t24_lab)

# llama.cpp

> [!IMPORTANT]
> **This is the PrismML fork of llama.cpp**, the main line behind the [Bonsai](https://huggingface.co/collections/prism-ml/bonsai) models (branch `prism`, developed as `prism-v7`). It tracks current mainline llama.cpp and adds the fork's low-bit formats and runtime features on top.
>
> **New here? Start with the [Bonsai-demo](https://github.com/PrismML-Eng/Bonsai-demo) repo.** It downloads the right models and the correct prebuilt binaries for your hardware/backend automatically.
>
> **Which ternary model file to use:**
>
> - `*-PQ2_0.gguf` (fork group-128, ggml id 142): preferred on Metal, CUDA, HIP and CPU. About 6% smaller than group-64.
> - `*-Q2_0_g64.gguf` / 27B `*-Q2_g64.gguf` (official group-64, ggml id 42): runs on every backend here AND on mainline llama.cpp. If unsure, use this. Newer model releases name this file plain `*-Q2_0.gguf`.
> - `*-Q2_0.gguf` on OLDER model repos is the **deprecated legacy format** (group 128 stored as id 42). It does not load on these builds; the error tells you which file to get instead. If you must run it, use the frozen [`prism-v5`](https://github.com/PrismML-Eng/llama.cpp/tree/prism-v5) line and its final release [`prism-b9601`](https://github.com/PrismML-Eng/llama.cpp/releases/tag/prism-b9601-68faa14).
>
> **Speculative decoding (dspark)** is supported via mainline's draft-dspark plus fork patches. Drafters published for older model releases need a one-time conversion with `gguf-dspark-to-dflash` (see [SPECULATIVE.md](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/SPECULATIVE.md) in Bonsai-demo); newer releases ship ready-to-use drafters.
>
> Do NOT build from `prism-v6` (stale mid-migration snapshot) and do NOT mix this fork's `ggml-*` libraries with a stock llama.cpp build.

## Quick start

A few options to get `llama.cpp` installed on your machine:

```bash
# curl
curl -LsSf https://llama.app/install.sh | sh

# powershell
irm https://llama.app/install.ps1 | iex
```

- Visit https://llama.app and follow the instructions
- Run with Docker - see our [Docker documentation](docs/docker.md)
- Download pre-built binaries from the [releases page](https://github.com/ggml-org/llama.cpp/releases)
- Build from source by cloning this repository - check out [our build guide](docs/build.md)

Once installed:

```sh
# Download and run a model directly from Hugging Face
llama cli -hf ggml-org/Qwen3.5-0.8B-GGUF

# Launch OpenAI-compatible API server
llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF
```

## Description

The main goal of `llama.cpp` is to enable LLM (and VLM) inference with minimal setup and state-of-the-art performance on
a wide range of hardware - locally and in the cloud.

- Plain C/C++ implementation without any dependencies
- Apple silicon is a first-class citizen - optimized via ARM NEON, Accelerate and Metal frameworks
- AVX, AVX2, AVX512 and AMX support for x86 architectures
- RVV, ZVFH, ZFH, ZICBOP and ZIHINTPAUSE support for RISC-V architectures
- 1.5-bit, 2-bit, 3-bit, 4-bit, 5-bit, 6-bit, and 8-bit integer quantization for faster inference and reduced memory use
- Custom CUDA kernels for running LLMs on NVIDIA GPUs (support for AMD GPUs via HIP and Moore Threads GPUs via MUSA)
- Vulkan and SYCL backend support
- CPU+GPU hybrid inference to partially accelerate models larger than the total VRAM capacity

The `llama.cpp` project is build on top of the [ggml](https://github.com/ggml-org/ggml) library.
